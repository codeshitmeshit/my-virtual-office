# Virtual Office 系统级 UI 标准升级设计

日期：2026-08-09  
状态：弹窗与通知范围增补后待书面确认

## 目标

本期只完成两件事：先在 Figma 中选定并对齐一套页面视觉基准，再将基准沉淀为 Virtual Office 的系统级 UI 规范。规范供后续产品设计、Agent 生成 UI 和专门的前端改造阶段使用；本期不修改前端代码，也不执行历史页面迁移。

## 本期边界

- 先对齐“页面应该长什么样”，再抽取基础规范和组件规范。
- 所有产出位于现有 Figma 文件的标准页内，保持可编辑、可搜索、可直接链接。
- 现有产品页面只作为视觉和行为样本读取，不在本期逐页重画。
- 代码对齐、共享组件改造和旧页面迁移另立后续需求，不属于本期验收。

## 权威性与适用范围

- 标准页名称调整为 `00 · SYSTEM UI STANDARD · AI START HERE`，继续保持为文件第一页。
- Cover 明确标注 `Authoritative Standard`、适用范围、优先级和例外流程。
- 适用于 Web 前端的颜色、字体、间距、圆角、组件、图标、交互状态与危险操作。
- 业务页面可以增加领域组件，但不得重新定义全局基础组件或改变语义颜色。
- 当旧页面或现有代码与标准页冲突时，本期只记录差异，不修改实现。
- 后续前端改造阶段以已确认的标准页为目标基准，并单独制定迁移范围与顺序。
- 例外必须在业务设计中写明原因、影响范围和回归标准，不能形成隐式分支规范。

## 图标与动作规范

第一版纳入以下常用动作：

- 添加：Plus
- 编辑：Edit
- 删除：Trash
- 移除关联：Remove / Minus
- 清空输入：Clear / Close Circle
- 关闭表面：Close
- 返回：Arrow Left
- 展开与收起：Chevron Down / Up
- 更多操作：More Horizontal
- 刷新或重试：Refresh
- 成功、警告与错误：Check、Warning、Error

图标采用统一线性风格、相同描边语言和标准尺寸。图标不能单独依赖颜色表达含义；没有文字标签的图标按钮必须提供 tooltip 和可访问名称。删除统一使用 Trash，关闭统一使用 Close，清空与删除不得共用同一语义。

## 危险等级

动作分为三级：

### Level 1：普通移除

用于移除筛选项、标签、草稿行或可立即恢复的关联。默认使用中性色；完成后提供即时反馈，适用时提供撤销。

### Level 2：可恢复删除

用于删除可从回收站、历史记录或服务端恢复的数据。触发控件使用危险色；执行前使用确认弹窗，明确对象名称和影响；成功后可提供撤销或恢复入口。

### Level 3：永久删除

用于不可逆或高影响操作。必须使用强确认弹窗，明确不可恢复、关联影响与对象名称；必要时要求输入对象名称确认。主按钮文案必须描述动作，例如“永久删除办公室”，不能只写“确定”。

## 交互状态

所有可交互组件至少定义：`Default`、`Hover`、`Focus`、`Disabled`、`Loading`、`Success`、`Error`。

- Focus 必须有可见轮廓，不能只改变背景色。
- Loading 时避免重复提交，并保留动作语义文案。
- Disabled 必须同时体现视觉与实际不可操作状态。
- 失败时保留用户输入和上下文，错误信息贴近触发位置，并提供明确重试方式。
- 成功反馈不得包含密钥或敏感数据。

## 删除交互流程

标准流程为：

`触发危险操作 → 展示影响与对象 → 用户确认或取消 → 提交中禁用重复操作 → 成功反馈及恢复入口（若可恢复）／失败保留上下文并允许重试`

关闭确认弹窗、点击取消或按 Escape 均不得产生删除副作用。提交过程中不允许通过重复点击生成多个请求。永久删除成功后，界面必须转移到仍然有效的状态，不能停留在已不存在对象的详情页。

## 弹窗与覆盖层规范

弹窗根据任务复杂度和是否需要保留页面上下文分为六类：

- `Alert Dialog`：只告知必须被看到的结果或阻塞信息，通常只有一个确认按钮。
- `Confirm Dialog`：要求用户在继续与取消之间作出明确选择。
- `Destructive Confirm`：承载 Level 2 或 Level 3 危险操作，按钮文案必须描述具体动作。
- `Form Modal`：承载短表单，适用于字段较少、无需长时间导航的编辑任务。
- `Large Workflow Modal`：承载设置、导入、配置等复杂流程，使用稳定 Header、分类导航、滚动内容和固定 Footer。
- `Drawer`：在保留原页面上下文的同时提供辅助查看或编辑，不用于必须阻断用户的高风险确认。

所有弹窗必须明确：

- 尺寸级别、最大高度、内容滚动区域和移动端降级方式。
- 标题、说明、关闭按钮、主次按钮的稳定位置和顺序。
- 点击遮罩、按 Escape、点击 Close 和点击 Cancel 的行为是否一致。
- 焦点进入、焦点锁定、关闭后焦点归还和键盘操作顺序。
- `Clean -> Dirty -> Validating -> Saving -> Success or Error` 状态。
- Dirty 状态关闭时的保存、放弃与继续编辑选择。
- 提交期间的禁用、重复提交防护、失败输入保留和重试入口。

弹窗选择原则：只需要短暂反馈时不使用弹窗；不需要阻断用户时优先 Inline Alert、Toast 或 Drawer；只有必须立即决定或存在显著风险时才使用阻断式 Dialog。

## 通知与反馈规范

反馈根据影响范围、持续时间和是否需要后续处理分为六类：

- `Toast`：短暂、低打扰、无需后续处理的操作结果。
- `Persistent Toast`：包含重试或显式关闭动作，不能自动消失。
- `Inline Alert`：与具体表单、字段、卡片或模块直接相关。
- `Banner`：影响整个页面、工作区或系统的持续状态。
- `Notification Item`：需要稍后查看、保留历史或进入通知中心的消息。
- `Badge / Dot`：只表达数量或未读存在状态，不能独立承载错误原因。

通知必须明确：

- `Success`、`Info`、`Warning`、`Error` 的图标、标题和语义颜色。
- 屏幕位置、最大宽度、堆叠方向、最大堆叠数量和新旧顺序。
- 自动消失时间；包含操作、重要警告或错误时不得自动消失。
- Hover 暂停、手动关闭、操作按钮、重试和失败后的状态保留。
- 重复消息的合并或计数规则，避免连续操作形成通知风暴。
- 可访问播报等级：普通结果使用非打断播报，阻塞错误使用高优先级播报。
- 通知内容不得包含密钥、令牌、完整敏感配置或不可撤销动作的唯一确认入口。

通知选择原则：字段问题使用 Inline Alert；页面级持续问题使用 Banner；简单操作结果使用 Toast；需要稍后处理或保留历史时使用 Notification Item。不要用 Toast 替代确认弹窗，也不要用 Badge 替代可读错误信息。

## Agent 使用规则

标准页 Cover 增加以下机器可读、可搜索的指引：

1. 开始任何 UI 工作前先读取本页。
2. 优先复用本页的变量、组件和状态，不复制后自行修改。
3. 先判断动作语义与危险等级，再选择图标和颜色。
4. 新增通用模式时先更新标准页，再用于业务页面。
5. 业务需求与标准冲突时显式记录偏差，不得静默创造第二套规范。

## 验收标准

- 标准页仍位于 Figma 文件第一页，标题明确表达其权威性。
- 删除、关闭、清空与移除拥有不同且一致的图标与语义说明。
- 三种危险等级均包含触发、确认、加载、成功、失败和恢复规则。
- 图标按钮满足可访问名称、tooltip 和最小点击区域要求。
- 新增组件复用现有语义变量，不引入第二套颜色、字体或间距体系。
- 页面无裁切、空文本、占位内容、默认图层名或不一致字体。
- 标准页明确区分本期 Figma 规范产出与后续前端实施工作。
- 六类弹窗和六类通知均具有清晰的使用条件、禁止场景、状态与行为规则。
- Dialog、Drawer、Toast、Inline Alert、Banner、Notification Item 和 Badge 之间不存在语义重叠。
