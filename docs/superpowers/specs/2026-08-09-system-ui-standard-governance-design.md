# Virtual Office 系统级 UI 标准升级设计

日期：2026-08-09  
状态：待书面确认

## 目标

将 Figma 文件中的 `00 · AI UI Reference · START HERE` 从视觉参考升级为 Virtual Office 全系统前端的权威 UI 标准。后续新增、重构或由 Agent 生成的前端界面必须优先读取并遵循该标准；现有界面采用渐进式迁移，不要求一次性重写。

## 权威性与适用范围

- 标准页名称调整为 `00 · SYSTEM UI STANDARD · AI START HERE`，继续保持为文件第一页。
- Cover 明确标注 `Authoritative Standard`、适用范围、优先级和例外流程。
- 适用于 Web 前端的颜色、字体、间距、圆角、组件、图标、交互状态与危险操作。
- 业务页面可以增加领域组件，但不得重新定义全局基础组件或改变语义颜色。
- 当旧页面、现有代码与标准页冲突时：新开发以标准页为准；旧页面在被修改时同步迁移。
- 例外必须在业务设计中写明原因、影响范围和回归标准，不能形成隐式分支规范。

## 标准页结构调整

现有内容保留并扩展为六个连续区块：

1. `00 · Governance`：权威声明、Agent 阅读顺序、适用范围和迁移原则。
2. `01 · Foundations`：现有颜色、字体、间距和圆角。
3. `02 · Components`：现有输入、选择、开关、按钮、导航和弹窗等组件。
4. `03 · Icons & Actions`：新增系统图标、动作语义和危险等级。
5. `04 · States & Destructive Flows`：统一状态与删除确认流程。
6. `05 · Composition & Adoption`：组合示例和新旧页面对齐检查表。

## 图标与动作规范

第一版纳入以下常用动作：

- 添加：Plus
- 编辑：Edit
- 删除：Trash
- 移除关联：Remove / Minus
- 清空输入：Clear / Close Circle
- 关闭表面：Close
- 返回：Arrow Left
- 展开与收起：Chevron Down / Up
- 更多操作：More Horizontal
- 刷新或重试：Refresh
- 成功、警告与错误：Check、Warning、Error

图标采用统一线性风格、相同描边语言和标准尺寸。图标不能单独依赖颜色表达含义；没有文字标签的图标按钮必须提供 tooltip 和可访问名称。删除统一使用 Trash，关闭统一使用 Close，清空与删除不得共用同一语义。

## 危险等级

动作分为三级：

### Level 1：普通移除

用于移除筛选项、标签、草稿行或可立即恢复的关联。默认使用中性色；完成后提供即时反馈，适用时提供撤销。

### Level 2：可恢复删除

用于删除可从回收站、历史记录或服务端恢复的数据。触发控件使用危险色；执行前使用确认弹窗，明确对象名称和影响；成功后可提供撤销或恢复入口。

### Level 3：永久删除

用于不可逆或高影响操作。必须使用强确认弹窗，明确不可恢复、关联影响与对象名称；必要时要求输入对象名称确认。主按钮文案必须描述动作，例如“永久删除办公室”，不能只写“确定”。

## 交互状态

所有可交互组件至少定义：`Default`、`Hover`、`Focus`、`Disabled`、`Loading`、`Success`、`Error`。

- Focus 必须有可见轮廓，不能只改变背景色。
- Loading 时避免重复提交，并保留动作语义文案。
- Disabled 必须同时体现视觉与实际不可操作状态。
- 失败时保留用户输入和上下文，错误信息贴近触发位置，并提供明确重试方式。
- 成功反馈不得包含密钥或敏感数据。

## 删除交互流程

标准流程为：

`触发危险操作 → 展示影响与对象 → 用户确认或取消 → 提交中禁用重复操作 → 成功反馈及恢复入口（若可恢复）／失败保留上下文并允许重试`

关闭确认弹窗、点击取消或按 Escape 均不得产生删除副作用。提交过程中不允许通过重复点击生成多个请求。永久删除成功后，界面必须转移到仍然有效的状态，不能停留在已不存在对象的详情页。

## Agent 使用规则

标准页 Cover 增加以下机器可读、可搜索的指引：

1. 开始任何 UI 工作前先读取本页。
2. 优先复用本页的变量、组件和状态，不复制后自行修改。
3. 先判断动作语义与危险等级，再选择图标和颜色。
4. 新增通用模式时先更新标准页，再用于业务页面。
5. 业务需求与标准冲突时显式记录偏差，不得静默创造第二套规范。

## 迁移策略

- 新页面：创建时即满足全部标准。
- 被修改的旧页面：采用“触达即迁移”，至少对齐本次修改所涉及的组件及相邻状态。
- 未修改的旧页面：纳入清单，按业务优先级逐步迁移。
- 共享组件优先迁移，页面级样式随后收敛，避免多个页面重复修复。
- 每次迁移检查视觉、键盘操作、危险行为、加载反馈与失败恢复。

## Figma 交付物

- 更新后的权威 Cover 与治理说明。
- 可复用的系统图标与 Icon Button 组件。
- 删除、关闭、清空、移除的正确和错误用法对照。
- Level 1–3 危险操作示例。
- 可恢复删除与永久删除确认弹窗示例。
- 完整状态矩阵。
- 全系统采用检查表和迁移优先级说明。
- 可供 Agent 直接定位的稳定命名与独立区块链接。

## 验收标准

- 标准页仍位于 Figma 文件第一页，标题明确表达其权威性。
- 删除、关闭、清空与移除拥有不同且一致的图标与语义说明。
- 三种危险等级均包含触发、确认、加载、成功、失败和恢复规则。
- 图标按钮满足可访问名称、tooltip 和最小点击区域要求。
- 新增组件复用现有语义变量，不引入第二套颜色、字体或间距体系。
- 页面无裁切、空文本、占位内容、默认图层名或不一致字体。
- 标准页提供新页面、旧页面和 Agent 三类采用规则。

## 非目标

- 本次不直接重构整个前端代码库。
- 本次不一次性重画所有历史业务页面。
- 本次不引入与现有 Virtual Office 视觉语言不兼容的第三方 UI Kit。
- 本次不将领域专属绿色状态提升为全局默认主色。
