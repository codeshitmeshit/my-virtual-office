# 系统设置大弹窗设计

## 目标

把主页面现有的 270px 左侧设置抽屉改为居中的大弹窗，让大量配置项更易浏览、编辑和扩展，同时保持现有配置字段、接口与保存行为兼容。最终在现有 Figma 原型文件中新增一张与实现一致的可编辑画板。

## 当前问题

- 设置内容被限制在 270px 单列中，标签、说明和输入框拥挤。
- 所有配置连续排列，用户需要长距离滚动才能找到目标项。
- 抽屉遮挡办公室画布，但仍缺少足够的编辑空间。
- 保存按钮位于内容末尾，长表单中不易触达。
- Figma 文件中尚无主系统设置界面的对应画板。

## 已确认方案

采用居中大弹窗与左侧分类导航：

- 桌面端弹窗目标尺寸为 960 × 680px，并限制在视口安全边距内。
- 背景使用半透明遮罩，保留办公室上下文但降低视觉干扰。
- 顶部固定标题、简短说明和关闭按钮。
- 左侧固定分类导航，右侧只展示当前分类的设置内容。
- 右侧表单在空间允许时采用两列布局；长说明、状态和复杂卡片跨两列。
- 底部固定取消与保存操作，保存继续调用现有 `mmSaveSettings()`。
- 小屏下弹窗切换为近全屏布局，分类导航变为横向可滚动标签，表单回落为单列。

## 信息架构

设置项按现有职责归为七类：

1. 连接：OpenClaw、Hermes。
2. Agent：Codex、Claude Code 及原生 Agent Provider。
3. 办公室：办公室名称、天气位置与天气效果。
4. 显示：气泡、名称、发送快捷键、超时、字号和语言。
5. 通知：飞书通知与飞书聊天通道。
6. 存储：Alibaba Cloud OSS 等持久化设置。
7. 高级：API Usage、PC Performance、Agent Browser、导入导出、重置与帮助。

默认打开“连接”。切换分类只改变可见区域，不销毁表单节点，避免丢失尚未保存的输入。

## 交互与状态

- 点击工具栏“菜单”打开弹窗，并加载当前设置。
- 点击关闭、取消、遮罩或按 Escape 关闭弹窗。
- 弹窗打开时锁定页面背景交互，并把焦点移入弹窗；关闭后把焦点还给菜单按钮。
- 分类按钮展示选中态，并同步 `aria-selected` 和可见面板状态。
- 保存期间沿用现有状态反馈；成功后可保持弹窗打开，以便用户确认或继续调整。
- 测试连接、测试天气等局部操作继续在所属分类内展示结果。
- 危险操作保留独立的警示视觉，不与主保存按钮并列。

## 实现边界

遵循仓库的模块化约束，把新增行为放到聚焦文件中：

- 新建 `app/settings-modal.css`，负责遮罩、弹窗、分类导航、响应式布局和可访问状态样式。
- 新建 `app/settings-modal.js`，负责分类映射、导航生成、打开/关闭增强、焦点与键盘交互。
- `app/index.html` 只做必要的资源引入、语义属性和轻量挂载标记，不承载新的业务逻辑。
- `app/main-menu-settings.js` 保留配置读取、测试与保存职责；如需接入新壳层，只增加薄委托。
- 现有字段 ID、后端 API 和本地存储键保持不变。

## Figma 交付

在文件 `My Virtual Office｜核心产品原型` 的 `Prototype` 页新增顶层画板：

- 名称：`系统设置 · 大弹窗`
- 画板尺寸：1512 × 742px，与现有核心原型一致。
- 展示办公室背景、遮罩和 960 × 680px 设置弹窗。
- 默认呈现“连接”分类，包含 OpenClaw 与 Hermes 的代表性表单状态。
- 图层使用 Auto Layout；导航项和重复表单结构组件化。
- 视觉沿用现有深色像素风、金色强调色、紧凑控件和边框语言。

## 测试与验收

- 静态测试验证新样式与脚本已加载、旧字段 ID 和保存入口未被破坏。
- DOM 测试验证打开、关闭、Escape、遮罩关闭、分类切换和未保存输入保留。
- 浏览器测试验证桌面端弹窗尺寸、固定头尾、内容滚动和背景遮罩。
- 响应式测试验证窄视口下近全屏、横向分类和单列表单。
- 运行现有设置相关测试，确认配置加载、局部测试和保存行为回归通过。
- Figma 完成后分别检查完整画板与弹窗局部截图，确认无裁切、重叠、占位文本或字体偏差。

## 非目标

- 不修改任何设置字段的业务含义或后端配置格式。
- 不在本次改造中重写设置保存流程。
- 不新增搜索、配置预设、权限分级或多步骤向导。
- 不覆盖或删除 Figma 中现有画板。
