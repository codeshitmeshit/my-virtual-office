# 技能库智能整理：真实浏览器验收清单

- [ ] 使用独立开发环境，确认当前部署 commit 与测试记录一致。
- [ ] 安装并启动真实 OpenClaw，档案室中已有且仅有一个可用的“档案管理员”。
- [ ] 服务端设置 `VO_SKILL_LIBRARY_ORGANIZATION_ENABLED=1` 后重启。
- [ ] 准备有效的 `VO_MANAGEMENT_TOKEN`。
- [ ] 使用 Chrome 最新稳定版；打开 DevTools 的 Console 和 Network，并启用 Preserve log。
- [ ] “默认标签”中没有真实业务 Skill；测试结束后可安全清理测试数据。

## 2. 入口、布局与术语

- [ ] 从侧边栏打开“技能库”，弹窗正常出现。
- [ ] 顶部操作从左到右为“智能整理、创建技能、导入技能”，并整体右对齐。
- [ ] 技能库中没有“浏览 MCP”或 MCP Registry 入口；MCP Registry 仍从原有独立入口打开。
- [ ] 页面没有“团队空间”、待入库、已入库、待整理或已整理等生命周期文案。
- [ ] 桌面宽度下呈现“分类 / 技能列表 / 技能详情”三列，卡片文字左对齐。
- [ ] 将浏览器宽度缩到 600px：布局变成单列，无横向滚动，顶部按钮没有溢出或被截断。
- [ ] 分类、卡片、详情栏和右侧边界间距一致，没有贴边、截断或异常大空白。

## 3. 中英文与无障碍

- [ ] 切换中文：按钮、内置分类、状态标记、空状态和错误文案均为中文。
- [ ] 切换英文：上述动态内容立即切换为英文，自定义分类名称保持原名。
- [ ] 搜索框、关闭按钮、分类导航、技能列表、详情栏和改类选择框均有可读的无障碍名称。
- [ ] 仅使用键盘可聚焦搜索、分类、技能卡片、整理按钮、分类选择和移动按钮。

## 4. 新建、导入与默认分类

- [ ] 新建 `browser-create-skill`，返回技能库后它位于“默认标签”。
- [ ] 导入一个 `browser-import-skill` 的 `SKILL.md`，它也位于“默认标签”。
- [ ] 两个 Skill 均只有一个主分类；没有额外的整理状态字段或状态标签。
- [ ] “全部技能”和“默认标签”的数量同步增加。
- [ ] 搜索 `browser-create` 只显示匹配卡片；清空搜索恢复列表。
- [ ] 详情栏来源显示“本地技能库 / Local Skills Library”。

## 5. 权限弹窗

- [ ] 在 Console 执行 `sessionStorage.removeItem('voManagementToken')`，重新点击“智能整理”。
- [ ] 管理令牌弹窗显示在技能库弹窗上方，背景技能库不可误操作。
- [ ] 取消弹窗：不启动整理，按钮恢复可用。
- [ ] 输入错误令牌：请求失败且不产生整理 run。
- [ ] 再次点击并输入正确令牌：只产生一个启动请求。
- [ ] Network 中未授权请求返回 `403` 和 `management_token_required`，授权重试携带 `X-VO-Management-Token`。

## 6. 真实档案管理员整理

- [ ] 点击“智能整理”后立即出现“档案管理员正在整理技能库…”标记。
- [ ] 整理期间按钮和手工改类控件置灰；连续点击不会产生第二个 run。
- [ ] Network 中只有一个 `POST /api/skills-library/organization/runs`。
- [ ] 打开档案室，现有档案管理员显示 working，当前工作为技能库整理；没有创建新的机器人。
- [ ] 整理运行时发起一次档案数检查或手动档案整理，后到操作立即得到 busy 提示，不排队执行。
- [ ] 整理完成后轮询停止；Network 不再每 2 秒请求技能库。
- [ ] 成功项从“默认标签”移到对应分类，分类数量实时更新。
- [ ] 如果档案管理员创建了普通分类，其名称、计数和所属 Skill 正常显示。
- [ ] 准备一个用途明确但不属于现有分类的 Skill；整理后档案管理员新建普通分类并将其移入，不得以“没有合适分类”为由标记失败。
- [ ] 顶部仅显示轻量结果标记，不出现独立技能整理日志或详细成功报告。
- [ ] 档案室现有活动日志新增且仅新增一条本次技能整理终态摘要。

## 7. 失败项与手工修复

若真实模型没有自然产生失败项，可在独立环境中准备一个无法按 UTF-8 读取的测试 `SKILL.md`，再启动一次整理；不要修改真实业务 Skill。

- [ ] 部分失败时，成功项保持已移动，失败项仍在“默认标签”。
- [ ] 顶部标记显示准确的失败数量。
- [ ] 点击失败标记后自动选择“默认标签”，列表只显示失败项。
- [ ] 每个失败卡片显示“归类失败”徽标。
- [ ] 每个失败卡片在徽标下显示具体、安全的失败原因；原因中不包含本地私有路径或原始模型输出。
- [ ] 选中失败 Skill 后，右侧详情显示同一个失败原因。
- [ ] 中文与英文界面下，失败原因字段和无障碍名称均使用对应语言。
- [ ] 分别验证模型信息不足、响应校验失败、超时、Skill 不可读和服务重启中断时，界面能展示可区分的原因。
- [ ] 在详情栏一次只移动一个失败 Skill，不提供批量或拖拽改类。
- [ ] 移动一个失败项后，失败数量立即减 1，该卡片从失败筛选中消失。
- [ ] 修改期间再次点击“移动”不会重复提交。
- [ ] 最后一项修复后，顶部标记变为“归类失败项已全部处理”。
- [ ] 模拟 catalog revision 冲突时，页面刷新最新数据，不用旧值覆盖新分类。

## 8. 禁用与异常状态

- [ ] “默认标签”为空时，“智能整理”置灰，提示没有需要整理的技能。
- [ ] 在档案室暂停档案管理员后，整理按钮置灰并提示管理员不可用；恢复后按钮重新可用。
- [ ] 档案管理员正在执行其他档案工作时，整理按钮置灰并显示忙碌原因。
- [ ] 在没有档案管理员的独立环境中，启动请求明确报错，不创建或替换 Agent。
- [ ] 整理中刷新浏览器：页面恢复 running 标记并继续轮询。
- [ ] 模拟服务重启后，遗留 running 结果转为失败/中断，管理员不再永久 busy，测试 Skill 仍在“默认标签”。

## 9. 结果标记持久化

- [ ] 完成、部分失败或已解决标记在刷新页面后仍存在。
- [ ] 点击“关闭”后标记消失；再次刷新仍保持关闭。
- [ ] 下一次整理结果会替换上一次结果，并重新显示。

## 10. 回滚与兼容性

- [ ] 关闭 `VO_SKILL_LIBRARY_ORGANIZATION_ENABLED` 并重启后，不能启动新的整理。
- [ ] 关闭开关后，新建、导入、编辑、应用到 AI 和删除 Skill 仍正常。
- [ ] 关闭开关不会删除或重写现有 `.vo-library-catalog.json`。
- [ ] 直接在技能库目录新增一个合法 Skill 文件夹后，刷新页面可见，且默认归入“默认标签”。
- [ ] 直接删除测试 Skill 后，授权执行下一次技能写操作会清理陈旧分类元数据。

## 11. 开发机自动验收

在专用环境中执行：

```bash
VO_TEST_URL=http://127.0.0.1:8090 \
VO_MANAGEMENT_TOKEN='<development token>' \
VO_LIVE_ACCEPTANCE_ALLOW_MUTATION=1 \
VO_LIVE_SKILL_COUNT=103 \
.venv/bin/python tests/skill_library_organization_live_acceptance.py
```

- [ ] 输出包含 `ok: True`。
- [ ] `skillCount` 为 `103`。
- [ ] evidence 包含 management-token、default-intake、real-archive-manager-start、terminal、manual-repair 和 archive-manager-activity。
- [ ] 脚本结束后测试 Skill 已自动清理。
